HokieBikeRack firmware - known bugs and limitations
==================================================

Board: Arduino Uno R3 since 2026-11-10 (was ESP32; old code = git tag esp32-final).

1. [FIXED 2026-11-02] Event upload could freeze the main loop for up to 8 seconds
   Was:    syncEvents() ran http.POST() inside loop() with an 8 s timeout, so card
           taps, tamper checks and the re-lock timer stopped while it waited.
   Fix:    (ESP32) network work moved to its own FreeRTOS task.
   Now:    The Uno version has no network code at all, so this can't happen.
   Lesson: see docs/notes/firmware.md, "Non-blocking code".

2. Uno firmware not tested on real hardware yet (2026-11-10)
   What:   It builds for the Uno (846 bytes RAM, 21 KB flash) with no warnings.
           The PC unit tests compile, but Windows Application Control on this
           laptop blocks running them, so they have NOT been run since the port.
           Run `pio test -e native` on another machine, then follow
           docs/notes/hardware-test-checklist.md on the Uno.
   Status: Open.

3. The rack is offline: nothing reaches the backend or the apps
   Why:    The Uno has no Wi-Fi. Events (granted, denied, tamper) are printed
           to the serial monitor only. The dashboard, rider app ("your bike is
           parked here", alarm warnings) and HokieP linking need a networked
           rack; the simulator (tools/device_simulator.py) still stands in for one.
   Fix later: Uno R4 WiFi, or an ESP-01 Wi-Fi module on a serial port, or go
           back to the ESP32 (git tag esp32-final).
   Status: Accepted (board choice, 2026-11-10).

4. Card list never expires; removing access is manual
   Why:    The Uno has no clock, so the ESP32's "72 h snapshot" rule can't
           exist. A card stays allowed until someone runs `unenroll` (and taps
           it) or `list` + `remove <n>` at the rack.
   Fix later: an RTC module (e.g. DS3231) would allow expiry dates.
   Status: Accepted for the demo.

5. Anyone with a USB cable can enrol a card
   Why:    `enroll`, `add` and `wipe-cards` are serial commands with no password.
   Fix:    Keep the Uno inside the locked housing; don't leave the USB port exposed.
   Status: Accepted for the demo.

6. Card UID matching can be fooled by cloned cards
   Why:    The PN532 reads the card's public ID. Cheap "magic" cards can copy it.
           We hash the ID (HMAC) so it isn't exposed, but a clone hashes the same.
   Fix later: cards with real cryptography (e.g. MIFARE DESFire EV2/EV3).
   Status: Accepted for the demo; documented in docs/SECURITY.md.

7. Servo position is not verified
   Why:    A 3-wire MG90S has no position feedback. "Unlocked" means "told to
           unlock", not "is unlocked". A jam is not detected.
   Status: Accepted for the demo.

8. Max 63 cards
   Why:    1 KB EEPROM, 16 bytes per card. `enroll` says "list is full" after that.
   Status: Accepted for the demo.
